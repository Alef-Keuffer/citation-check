# Grilling record: citation-check design (2026-11-14 to 2026-11-16)

Goal: a reusable tool for checking the citations an AI writes into pandoc Markdown reports, grown from `cite.py` in the Places report (feup.devops.places PR 17). It started from the question "are there tools that fix checking AI citations?". The answer was no for local book PDFs cited by chapter, so we design our own.

Vocabulary: see `GLOSSARY.md`. Decisions with their reasoning: see `docs/adr/0001` to `0006`.

## The problem

The failures to catch:
- (b) the locator is wrong: the cited chapter doesn't say it;
- (c) the claim overstates its source;
- (d) checking by hand takes too long.

Failure (a), an invented reference, is caught by the ISBN match when the source is at hand, and by the catalogue levels when it isn't.

## Decisions

1. **Own tool** (ADR-0001), extending cite.py, in repo `Alef-Keuffer/citation-check`, symlinked into `~/.claude/skills/citation-check`. No deadline: the tool is separate from the Places delivery.
2. **Conventions.** The tool finds the report through the one pandoc defaults file that names both `bibliography` and `input-files`. Sources live in `docs/sources/` of the main checkout. A PDF is matched to its entry by the ISBN or DOI it prints in its first pages, or by the entry's `file` field when it prints neither.
3. **Passages in endnotes** (ADR-0002). `[@key, ch. 3]^["passage" (p. 71)]`, or `(PDF p. 104)` when the source prints no page numbers, printed in a quotations appendix through `enotez`. Every citation needs a passage except a pointer citation, `[see @key]`, which only the author writes. A citation with several keys is split. No `para.`.
4. **`p.` is the printed page**, read from running headers or footers, roman pages included; `p.` on a source with no printed numbers fails.
5. **Acquire and verify** (ADR-0003). Verify is deterministic and offline. Acquire is off by default, switched on per run, and fetches only openly available sources: no Anna's Archive. It saves dated copies.
6. **Levels** (ADR-0004): Unknown, Exists, Located, Found remotely, Verified. Only Verified passes, with a single mode. Digests are out of scope.
7. **Entries checked against the source** (ADR-0005). The year is the copyright year; the catalogue's year may differ by one.
8. **Judge** (ADR-0006). A decision model gives a support score from a yes/no probability or a native score. Below the model's threshold, the citation escalates to an Opus subagent. The model and threshold are chosen by a test on the Places report's claims plus an overstated version of each.
9. **Tests.** Python's `unittest`, with fixtures generated at test time:
   - LaTeX-built PDFs with bookmarks, printed page numbers in running headers, roman-numeral front matter and an ISBN on the copyright page;
   - one PDF with no page numbers;
   - saved HTML pages;
   - recorded catalogue responses.

   The tests cover every locator type (`ch.`, `sec.`, ranges, `p.`, `pp.`, roman pages, PDF page, no locator, `see`) against every source type (book PDF, PDF without page numbers, web page, catalogue only, unknown). Live network tests run only when asked, and tests against real books run only when `docs/sources/` exists.
10. **Keys** come from the environment only: `GOOGLE_BOOKS_API_KEY` (already exported in `~/.zshrc`) and the judge model's key.
11. **Ticket order:** verify, then acquire and the levels, then judge.

## Questions for later

- Does the Google Books API with the user's key find real phrases from the three Places books and reject an invented one? If not, drop Found remotely.
- Does Clef 27B run on the M4 Max with 36 GB? If not, it leaves the judge test.
- Does the superscript of an `enotez` endnote link to the appendix?

## Out of scope

Digests, `para.` locators, a draft mode, Anna's Archive and other shadow libraries, manuscripts other than pandoc Markdown, checking the bibliography by generating it from catalogues.
